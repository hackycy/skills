# Goal Loop 维护约定

本文件适用于本目录中的 skill、模板、脚本和说明文档。它记录维护时必须保留的产品意图，不作为目标 effort 的执行上下文；不要把它复制到 `goal/`，也不要要求普通执行读取它。

## 保留意图

- 用户初始化一次，保存一份固定 prompt，此后反复复制同一份正文启动 Goal，直到整个 effort 完成。
- 固定 prompt 表达执行规则；Gate、Revision、slice、checkpoint 和检查状态由执行 agent 启动后读取。不得按这些状态生成“下一轮 prompt”。
- 用户无需选择 Gate、运行内部命令、查询 Revision 或手动分页。必要决策、环境恢复和合同要求的人工验收才需要用户输入。
- 一个 Goal 可以连续完成多个 slice。保存 checkpoint 后继续工作，slice 不是用户必须重新启动任务的单位。Gate 通过后结束本轮，下次自动接续直接后继。
- 优化可以改变内部流程，但不能增加用户续接操作。控制面服务于执行和恢复，不演变成需要用户操作的工作流系统。

## 固定 prompt 的叙述视角

[固定 prompt 模板](references/goal-prompt-template.md)是 skill 帮用户想好、由用户直接发送给执行 agent 的话。撰写时把自己放在发出任务的用户位置：其中“我”指用户，“你”指接收任务的 agent；也可以使用省略主语的直接指令。

prompt 应表达“我要你完成什么、遵守什么约束、怎样确认完成或交接”。它不是 skill 对用户的使用说明，也不是维护者向旁观者描述用户与 agent 的关系。

| 不合适的视角 | 应表达的指令 |
| --- | --- |
| 用户下次发送同一份固定正文，由 agent 读取状态 | 每次收到这段指令，先读取当前状态并继续执行 |
| 向用户提供验收编号和入口 | 需要我验收时，向我提供验收编号、入口和最小清单 |
| 固定正文供用户反复使用 | 无需放进正文；复制和保存方式在 README 说明 |

- 内部命令可以出现在 prompt 中，因为执行者是 agent；不能要求发送 prompt 的人执行这些命令。
- 一次填好稳定路径和可执行入口。普通接续直接使用 `goal/` 内脚本，不依赖搜索 skill、重新加载 SKILL.md 或阅读脚本源码。
- 交付时用户应能直接复制正文，无需补写执行规则、选择当前 Gate 或替换状态值。
- 用“如果把这段话直接作为用户消息发送，是否自然且足以执行”检查全文，不能只机械替换“用户”为“我”。

## 文档各自服务谁

- [README](README.md)向使用者说明初始化、接续、验收和按需刷新执行材料；其中可复制的提示词同样采用用户发出指令的视角。
- [SKILL.md](SKILL.md)指导调用 skill 的 agent 准备和维护控制面。
- `references/` 保存按需查阅的合同、命令和存储细节；固定 prompt 模板遵循上面的用户视角。
- 正式使用与维护说明应自包含；必要规则保存在 `SKILL.md`、本文件或 `references/`，不依赖临时讨论资料。
- 文档直接描述行为和适用条件，避免“新布局”“新结构”“新版”等依赖重构时间点的相对措辞。任务资料的兼容处理由工具承担，使用者无需选择源版本或目标版本。

## 已有 effort 与执行材料刷新

普通接续保留已有记录、脚本和固定 prompt，不能因 skill 更新就自动替换入口、重新 bootstrap 或从 G0 开始。其他提交或其他会话中的改动，不代表当前用户改变了已明确表达的偏好。

用户明确要求调整执行材料时，在原 effort 使用可重复的 refresh：审阅已有提示词，保留明确的人工补充，与当前模板合并；仅实际冲突需要用户决定。备份被替换的文件，安装本地脚本和审阅后的完整正文，交付一次供用户重新保存。计划、baseline、Gate、Revision、checkpoint 的执行事实、检查结果和 history 保留。

Runbook 可以调整说明与结构，始终保存完整的当前检查快照；首次刷新可从相关旧 history 补齐必要事实，无法可靠还原则报告具体缺口。History 保留原文，纠正与合同重新验证追加记录。当前事实完整时，旧历史格式差异不阻断执行。具体机制见[控制脚本](references/control-script.md)和[存储与恢复](references/storage-and-recovery.md)。

## 上下文与验证

history 按 Gate 分离是为了按需追溯，checkpoint 用于恢复当前工作。每项检查只保存最新状态，Gate 切换后替换当前检查详情。默认 context 输出可行动状态，不输出内部证据元数据；普通执行读取已校验状态与必要合同，诊断时才读相关历史。控制输出长度不能静默丢失约束或验收条件，不应随执行轮数增长。

维护完成前，核对固定正文的用户视角、重复使用能力、连续 slice 行为和已有进度保留。运行仓库要求的 lint、检查相对链接；修改模板或控制脚本时运行 `python -m unittest discover -s skills/goal-loop/tests`，确认生成正文仍能通过校验并直接调用本地入口。校验器不应因叙述视角调整而拒绝已有合法固定正文。
