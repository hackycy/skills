# Sample Requests

These examples show intended triggering and behavior. They are not visual templates.

## Operational page

> 做一个移动端 H5 设备告警列表，原生 HTML/CSS/JS。需要严重/一般/提示筛选，显示设备名、告警内容、时间、状态，底部有首页/设备/告警/我的。

Expected behavior: infer an operational high-density direction, implement directly, avoid card-per-record by default, and visually review if browser tooling exists.

## Consumer membership page

> 做一个咖啡品牌会员首页 H5，需要积分、距离下一等级、可兑换权益、最近消费记录。年轻一些，但不要像活动落地页。

Expected behavior: choose a warmer and more expressive direction than an operations page, while keeping it usable as a real app screen.

## Finance detail page

> 帮我做手机端账单详情，展示金额、状态、商户、时间、支付方式、退款入口。要让用户觉得可靠，不要太花。

Expected behavior: restrained finance direction, strong numeric hierarchy, conservative motion, explicit state/action handling.

## Redesign existing code

> 这个 H5 表单太丑了，功能不要动，重新设计并直接改代码。

Expected behavior: inspect current code, preserve behavior and field semantics, build a new page-specific Visual Contract, implement it, and render-review the result.
