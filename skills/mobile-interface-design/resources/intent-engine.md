# 意图引擎

在决定页面长什么样之前，先判断这个移动页面到底是干什么的。

除非用户要求设计理由，否则不要把这段分析直接输出。

## 从“人在场景中”开始，不从 persona 标签开始

不要写：

> 运营人员

更有用的是：

> 一名维修技术员正在厂区边走边查看尚未处理的设备告警。

不要写：

> 消费者

更有用的是：

> 一名老会员在排队时打开 App，想确认是否有可立即兑换的权益。

真实使用场景会影响密度、拇指可达性、动效、文案和首屏内容。

## 主要结果 / 使用模式

不要强迫所有页面只有一个“主动作”。先判断页面最核心的结果或工作模式。

常见模式包括：

- **任务型**：提交巡检、开始训练、确认预约；
- **扫描型**：快速看库存、告警、记录；
- **比较型**：比较时段、套餐、数值；
- **监控型**：持续观察状态、行情、调度；
- **浏览型**：发现内容、商品、地点；
- **阅读型**：文章、账单、详情；
- **对话型**：消息、客服、协作；
- **表单型**：输入、验证、提交。

页面可以有 dominant mode，也可以有一个清晰 outcome，但不必把所有其他任务都压缩成一个 CTA。

## 使用频率

- 低频：开户、注销、特殊活动；
- 偶尔：预约、结账、资料设置；
- 高频：消息、任务、订单操作；
- 持续：监控、调度、扫描、行情。

高频界面通常允许更高密度，同时更应该减少装饰性摩擦。

## 任务压力与错误成本

- 放松 / 探索；
- 常规；
- 时间敏感；
- 高风险 / 容错低。

压力越高，越需要：

- 少歧义；
- 稳定对齐；
- 清晰区分状态和动作；
- 更保守的动效；
- 对不可逆操作提供更明确确认。

## 信息密度

从任务和内容决定密度，不从审美偏好决定。

- 稀疏：一个焦点对象或单一决定；
- 平衡：混合内容和若干动作；
- 紧凑：重复记录、监控、比较、运营处理。

## 情绪表达强度

页面需要表达多少品牌情绪？

- 低：运营、设置、高风险工具；
- 中：金融、效率、预约；
- 高：生活方式、娱乐、编辑内容、探索型消费。

情绪表达不得模糊操作含义。

## 主导内容形态

识别页面主要由什么组成：

- 重复记录；
- 单个详情对象；
- 表单 / 输入；
- 数字 / 状态；
- 图片 / 商品；
- 长文本；
- 地图 / 位置；
- 对话；
- 时间 / 日历；
- 步骤 / 进度；
- 路线 / 行程。

构图应该从内容形态出发，而不是默认把所有东西包进卡片。

## 动作结构

判断：

- 哪些动作高频；
- 哪些动作次要；
- 哪些动作危险；
- 哪些动作针对重复行项目；
- 页面是否主要是只读状态。

进一步问：动作应该：

- 始终可见；
- 只在上下文出现；
- 放在理解必要信息之后；
- 在拇指区保持 sticky；
- 或者根本不存在，因为页面主要是信息型。

不要因为移动 App 常见 FAB，就默认添加悬浮按钮。

## 首屏价值契约

内部完成：

```text
首屏必须让用户理解：
- ...

首屏如果需要允许用户行动，则应能：
- ...
```

重点不是“第一屏必须完成任务”，而是**首屏每一块空间都要值得存在**。不要让巨大标题、品牌装饰或低价值筛选控件把真正内容挤到屏幕外。

## 判断倾向，而不是模板

这些只是倾向：

- 高频运营 + 高密度 → 紧凑层级、稳定扫描路径、明显状态、少装饰；
- 探索消费 + 图片主导 → 更强图像节奏、选择性促销强调；
- 金融 + 高错误成本 → 精确术语、克制颜色、稳定数字层级、保守动效；
- 阅读型 → 字体和阅读节奏优先于 chrome；
- 高风险表单 → 渐进分组、就地校验、明确完成态；
- 活动 / 低频 / 高情绪 → 可以允许更强表达；
- 旅程 / 时间敏感 → 当前所处位置和下一步优先于目的地装饰；
- 移动现场 / 光线差 → 更大的可点击范围、更清晰对比、更短标签、更少动效。

这些都不是页面模板。
