# 去模板化整理

快速、局部、保持行为不变地移除让界面显得由 AI 套模板生成的特征。不是完整重设计，也不新增产品能力。

## 第一遍：看渲染结果

按影响处理：

1. **无注意力策略**：单任务页面没有焦点，或专业工作台所有信息互相竞争。
2. **层级平坦**：不读文字无法区分主要、次要和元数据。
3. **布局单调**：整页相同卡片、gap 和密度。
4. **颜色怯弱/泛滥**：多个低承诺浅色平均铺开，或一个 accent 涂遍全屏。
5. **边框代替结构**：到处用线画分组。
6. **后台组件 bingo**：新增区域无理由带上 Search、Filter、Table header、KPI cards 等模板痕迹；去模板化模式只在不改变业务行为的前提下移除纯装饰/重复入口，涉及真实功能则记录给设计评审，不擅自删功能。

## 第二遍：扫描当前 diff

### Token 与颜色

泛化硬编码值映射到项目已有 semantic token；竞争 accent 收敛；装饰性渐变/色块删除或赋予真实语义。

### 字体

已有方向时移除无理由默认字体；尺寸单独承担的层级补充字重与颜色；动态数字使用 `tabular-nums`。

### 表面与深度

刺眼边框、剧烈 elevation、混乱 depth strategy 收敛；嵌套圆角以视觉同心为准。

### 状态与动效

补齐当前范围真实交互所需状态；把 `transition: all` 改为明确属性；高频操作移除无意义动画；遵守 reduced motion。

点击目标不要机械扩大到 44px：按输入环境与可访问性需求处理，确保至少满足适用的 WCAG 2.2 目标尺寸/间距要求，并避免相邻目标误触。

### 间距与结构

随机值吸附到既有尺度；移除负 margin 抵消父 padding、逃生式 `calc()`、为绕开正常流而 absolute positioning。

### 重复实现

`<div onClick>` 改为真实语义控件；复杂 dropdown/select/modal/tooltip 优先项目组件或成熟 primitive；重复长样式提取组件或 variant；已有 token 时不用硬编码。

## 不属于 slop

- 有明确任务理由的搜索、筛选、侧栏、表格或批量操作
- 与意图一致且执行成功的大胆选择
- 内容驱动的不对称布局
- 当前 diff 之外旧问题
- system.md 已确认且仍然合理的决定

## 护栏

- 保持业务行为不变。
- 修改小而聚焦；需要重建信息架构或产品流程时停止，转入设计评审。
- 不为了“去模板”而删除真实功能。
- 输出聚焦有变化的类别，说明 Before / After 和定位。
