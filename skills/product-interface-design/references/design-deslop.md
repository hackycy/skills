# 去模板化整理

用于快速移除“标准 AI 后台”特征，同时保持业务行为不变。范围默认限于当前 diff 或用户指定区域。

## 第一遍：先看任务结构

在看颜色前，先找这几类模板化问题：

1. **KPI 卡片抢占主任务**：真正任务是处理记录，却把顶部 25–35% 空间给了泛化指标卡。缩减或移入辅助区。
2. **所有内容都卡片化**：列表、筛选、说明、统计都包成同样圆角卡片。恢复页面层级，让主工作区成为连续表面。
3. **表格退化成卡片列表**：桌面需要比较，却把每行变成独立卡片。恢复列对齐和扫描效率。
4. **操作全部藏进 overflow**：把高频安全动作稳定露出，低频动作才进入菜单。
5. **筛选只存在于弹窗里**：关闭筛选器后看不见当前 scope。增加可见摘要或 chips。
6. **详情破坏工作上下文**：仅在不改变业务行为的前提下修复可恢复的状态保持；需要重构路由时记录为评审项。

## 第二遍：视觉去模板化

- 找到 primary task 和 scanning anchors；不要机械制造巨大 Hero。
- 层级通过尺寸、字重、颜色共同建立。
- 收敛竞争强调色。
- 移除无意义渐变、彩色业务卡片和装饰色块。
- 用空间和轻微表面差异替代到处画线。
- 同一页面不要每个区块都使用完全相同 radius、padding、card elevation。

## 第三遍：密度

- 判断当前界面属于 compact / default / comfortable / touch-first。
- 将随机尺寸吸附到对应密度系统。
- 桌面高频后台不要机械把所有控件拉到 44px 高；必要时扩大 hit area 而不是扩大视觉体积。
- 表格行高、toolbar、filter chip、button、input 应属于同一密度语法。

## 第四遍：Token 与组件

- 颜色从 primitive 映射到 semantic，再在必要时映射 component token。
- 避免 `bg-white border-gray-200 text-gray-500` 和随机十六进制。
- 重复样式在第二次真实复用时抽成 variant / component。
- 复用项目已有 Button、Table、Popover、Dialog、Select 等原语。

## 第五遍：状态与动效

- 补齐当前范围内的 hover / active / focus / disabled。
- 将 `transition: all` 改为明确属性。
- 高频键盘操作移除动画。
- empty / no results / permission / error 若被错误混用，可在不扩业务的前提下修正文案与结构；需要新增数据状态时记录为后续。

## 护栏

- 不改变业务行为；
- 不为了“差异化”做奇怪布局；
- 不重写信息架构；
- 不把已有稳定产品惯例替换成设计师偏好；
- 遇到需要新增批量流程、保存视图、详情架构或路由状态时，停止局部整理并建议进入设计评审/重设计。
