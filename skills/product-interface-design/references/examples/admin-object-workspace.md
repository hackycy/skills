# 示例：Object Workspace

适合客户、订单、项目、账户、设备等复杂对象详情。

## 骨架

- Identity header：对象身份、主状态、少量关键动作；
- Summary rail：3–6 个真正影响判断的核心属性；
- Main work area：时间线、活动、订单项、任务或业务内容；
- Secondary context：关联对象、备注、元数据、系统信息；
- Dangerous actions：与高频操作分离。

## 关键决定

- 页面围绕对象的工作生命周期组织，不按后端数据表分区；
- 时间变化重要时优先时间线而不是静态字段墙；
- 高频编辑就地完成，复杂编辑进入专门流程；
- Tabs 只用于真正独立的任务域，不作为“放不下就切 tab”的垃圾桶。

## 反模式

- 12 张同样大小的属性卡片；
- 一个巨大标题 + 大量不可比较的键值对；
- 所有模块都用相同 card elevation；
- 关键状态和危险动作混在右上角同一菜单。
