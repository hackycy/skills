# 示例：Queue 审批台

适合客服、退款审核、风控、内容审核、工单处理。

## 骨架

- 左侧或主区：待处理队列；
- 右侧或详情区：当前对象与决策依据；
- 顶部：工作集、优先级、SLA、分配状态；
- 底部或固定动作区：Approve / Reject / Escalate / Snooze 等处理动作。

## 关键决定

- 每条为什么进入队列必须可解释；
- 优先级、风险、时限是 scanning anchors；
- 处理完成后可自动进入下一条；
- 支持 skip / assign / snooze（业务允许时）；
- 高风险拒绝/封禁等动作需要匹配风险的确认。

## 反模式

- 把 Queue 当普通 table，只多一个 Status 列；
- 每处理一条都返回列表再打开下一条；
- 处理动作藏在 overflow；
- 只用红黄绿表达优先级而没有文字/图标/排序依据。
